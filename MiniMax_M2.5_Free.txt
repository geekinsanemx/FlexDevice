9. EDGE CASES & FAILURE POINTS
================================================================================

9.1 High Priority Issues
-----------------------
1. NO FRAME SYNCHRONIZATION
   - Issue: process_binary_frame() scans for 0x00 but has no sync mechanism
   - Failure: If first 0x00 is missed, frames can join incorrectly
   - Location: at_commands.cpp:746-764

2. NO PACKET TYPE VALIDATION
   - Issue: parse_packet() only checks length, not type/opcode
   - Failure: Any 512-byte sequence with valid CRC is accepted
   - Location: binary_packet.cpp:288-299

3. NO SEQUENCE NUMBER VALIDATION
   - Issue: No SEQ validation in handlers
   - Failure: Host can send any sequence number, no wrap detection
   - Location: binary_handlers.cpp (all handlers)

4. NO FRAME RECEPTION TIMEOUT
   - Issue: binary_frame_pos grows until 0x00 or overflow
   - Failure: If 0x00 never arrives, buffer overflows and resets
   - Location: at_commands.cpp:750-753

9.2 Medium Priority Issues
-------------------------
1. COBS DECODE INCOMPLETE INPUT CHECK
   - Issue: Doesn't verify all input consumed before delimiter
   - Edge case: Malformed COBS could pass through

2. 8-BIT SEQUENCE WRAP RISK
   - Issue: seq is uint8_t, wraps at 255
   - Impact: After wrap, host/device may confuse old vs new packets

3. UUID NOT VALIDATED
   - Issue: UUID can be all zeros
   - Impact: Event correlation may fail

9.3 Low Priority Issues
-----------------------
1. PYTHON MAX_MESSAGE_INCONSISTENCY
   - Issue: 255 vs 248 constant difference
   - Impact: Python could accept messages firmware truncates

2. FLOAT ENDIANNESS UNDOCUMENTED
   - Issue: No spec mentions float byte order
   - Impact: Works on little-endian hosts, untested on big-endian
