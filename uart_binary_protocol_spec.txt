UART BINARY PROTOCOL SPECIFICATION v1.0 FLEX-FSK-TX (ESP32 <-> HOST)

1.  OBJECTIVE Define a robust asynchronous binary protocol over UART for
    communication between:

-   Host (Raspberry Pi, Python, C)
-   ESP32 (Heltec LoRa)

Requirements: - Full-duplex asynchronous communication - Non-blocking
operation - Error tolerance (CRC, retries) - Eliminate race conditions -
Support concurrent operations - Maintain legacy AT command support
(human interaction)

------------------------------------------------------------------------

2.  ARCHITECTURE MODEL

Message-oriented protocol (NOT command-response blocking model)

Message Types: - CMD: Host → ESP32 - RSP: ESP32 → Host (immediate
acknowledgment) - EVT: ESP32 → Host (asynchronous events)

Flow Example: CMD_SEND_FLEX → ← RSP_ACK ← EVT_TX_DONE

------------------------------------------------------------------------

3.  TRANSPORT LAYER

UART Configuration: - Baudrate: 115200 - 8N1 - Full duplex

Framing: - COBS encoding - Frame delimiter: 0x00

Final Frame: [COBS_ENCODED_PACKET] 0x00

------------------------------------------------------------------------

4.  PACKET STRUCTURE

struct Packet { uint8_t len; uint8_t type; uint8_t opcode; uint8_t
flags; uint8_t seq; uint16_t msg_id; uint8_t payload[N]; uint16_t crc16;
}

Field Definitions:

type: 0x01 = CMD 0x02 = RSP 0x03 = EVT

flags: bit0 = ACK_REQUIRED bit1 = RETRY bit2 = ERROR bit3 = PRIORITY

seq: - Transport sequence (0–255 rollover)

msg_id: - Unique per logical operation (generated by host) - Required
for async tracking

------------------------------------------------------------------------

5.  COMMAND DEFINITIONS

CMD_SEND_FLEX: payload: - uint64_t capcode - float frequency - int8_t
power - uint8_t maildrop - uint8_t msg_len - char message[msg_len]

CMD_GET_STATUS: payload: none

CMD_ABORT: payload: none

CMD_SET_CONFIG: payload: implementation-specific

CMD_GET_CONFIG: payload: none

CMD_PING: payload: none

------------------------------------------------------------------------

6.  RESPONSES

RSP_ACK: payload: - uint16_t msg_id - uint8_t status

status: 0x00 = ACCEPTED 0x01 = REJECTED 0x02 = QUEUE_FULL

RSP_STATUS: payload: - uint8_t device_state

device_state: 0 = IDLE 1 = WAITING_DATA 2 = WAITING_MSG 3 = TRANSMITTING
4 = ERROR

------------------------------------------------------------------------

7.  EVENTS

EVT_TX_DONE: payload: - uint16_t msg_id - uint8_t result

EVT_TX_FAILED: payload: - uint16_t msg_id - uint8_t error_code

EVT_ABORTED: payload: - uint16_t msg_id

EVT_PONG: payload: none

------------------------------------------------------------------------

8.  ERROR CODES

0x01 = INVALID_PARAM 0x02 = QUEUE_FULL 0x03 = RADIO_ERROR 0x04 = TIMEOUT
0x05 = BUSY

------------------------------------------------------------------------

9.  RELIABILITY

Transport Layer: - CRC16-CCITT - SEQ tracking - Retries

Application Layer: - msg_id correlation - async event reporting

------------------------------------------------------------------------

10. TIMING

ACK: < 10ms Retry timeout: 100ms Event timing: asynchronous

------------------------------------------------------------------------

11. LEGACY AT SUPPORT

-   AT commands remain supported in parallel
-   Intended for human/manual interaction (terminal)
-   Binary protocol is primary for host integration
-   Mode switching optional: AT+TXT → text mode AT+BIN → binary mode

------------------------------------------------------------------------

12. DESIGN PRINCIPLES

13. Every message must include msg_id

14. Never block waiting for execution

15. ACK != execution result

16. Events deliver final results

17. Host maintains operation state

------------------------------------------------------------------------

END OF SPEC
