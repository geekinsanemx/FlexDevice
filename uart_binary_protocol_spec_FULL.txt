UART BINARY PROTOCOL SPECIFICATION v1.0 FLEX-FSK-TX (ESP32 <-> HOST)

================================================== 1. OBJECTIVE
==================================================

Define a robust asynchronous binary protocol over UART for communication
between:

-   Host (Raspberry Pi / Python / C)
-   Device (ESP32 Heltec)

Requirements: - Full-duplex async - Non-blocking - Error tolerant (CRC +
retries) - Eliminate race conditions - Support concurrent operations -
Maintain legacy AT command interface (human interaction)

------------------------------------------------------------------------

2.  ARCHITECTURE MODEL

Message-Oriented Protocol (MOP)

Message Types: - CMD (Host → ESP32) - RSP (ESP32 → Host, immediate
acknowledgment) - EVT (ESP32 → Host, async events)

Flow Example:

CMD_SEND_FLEX → ← RSP_ACK ← EVT_TX_DONE

------------------------------------------------------------------------

3.  TRANSPORT LAYER

UART: - Baudrate: 115200 - 8N1 - Full duplex

Framing: - COBS (Consistent Overhead Byte Stuffing) - Frame delimiter:
0x00

Frame format: [COBS_ENCODED_PACKET] 0x00

Rationale: - Avoids delimiter collision - Minimal overhead - Proven
approach

------------------------------------------------------------------------

4.  PACKET STRUCTURE

struct Packet { uint8_t len; uint8_t type; uint8_t opcode; uint8_t
flags; uint8_t seq; uint16_t msg_id; uint8_t payload[N]; uint16_t crc16;
}

Field details:

type: 0x01 = CMD 0x02 = RSP 0x03 = EVT

opcode: 0x01 = SEND_FLEX 0x02 = GET_STATUS 0x03 = ABORT 0x04 =
SET_CONFIG 0x05 = GET_CONFIG 0x06 = PING

flags: bit0 = ACK_REQUIRED bit1 = RETRY bit2 = ERROR bit3 = PRIORITY

seq: - Transport-level sequence (0–255 rollover)

msg_id: - Application-level ID (CRITICAL) - Generated by host - Used to
correlate async responses/events

------------------------------------------------------------------------

5.  COMMAND DEFINITIONS

CMD_SEND_FLEX

payload: - uint64_t capcode - float frequency - int8_t power - uint8_t
maildrop - uint8_t msg_len - char message[msg_len]

------------------------------------------------------------------------

CMD_GET_STATUS

payload: none

------------------------------------------------------------------------

CMD_ABORT

payload: none

------------------------------------------------------------------------

CMD_SET_CONFIG

payload: - Implementation specific (frequency, power, defaults)

------------------------------------------------------------------------

CMD_GET_CONFIG

payload: none

------------------------------------------------------------------------

CMD_PING

payload: none

------------------------------------------------------------------------

6.  RESPONSES

RSP_ACK

payload: - uint16_t msg_id - uint8_t status

status: 0x00 = ACCEPTED 0x01 = REJECTED 0x02 = QUEUE_FULL

IMPORTANT: ACK means “received and queued” NOT “executed”

------------------------------------------------------------------------

RSP_STATUS

payload: - uint8_t device_state

device_state: 0 = IDLE 1 = WAITING_DATA 2 = WAITING_MSG 3 = TRANSMITTING
4 = ERROR

------------------------------------------------------------------------

7.  EVENTS (ASYNC)

EVT_TX_STARTED

payload: - uint16_t msg_id

------------------------------------------------------------------------

EVT_TX_DONE

payload: - uint16_t msg_id - uint8_t result

------------------------------------------------------------------------

EVT_TX_FAILED

payload: - uint16_t msg_id - uint8_t error_code

------------------------------------------------------------------------

EVT_ABORTED

payload: - uint16_t msg_id

------------------------------------------------------------------------

EVT_PONG

payload: none

------------------------------------------------------------------------

8.  ERROR CODES

0x01 = INVALID_PARAM 0x02 = QUEUE_FULL 0x03 = RADIO_ERROR 0x04 = TIMEOUT
0x05 = BUSY

------------------------------------------------------------------------

9.  RELIABILITY MODEL

Transport layer: - CRC16-CCITT - SEQ tracking - Retries (timeout
100ms) - Duplicate detection

Application layer: - msg_id correlation - async event delivery

------------------------------------------------------------------------

10. TIMING

ACK latency: < 10ms Retry timeout: 100ms Event timing: asynchronous
(depends on RF transmission)

------------------------------------------------------------------------

11. ASYNC BEHAVIOR

Example:

HOST: msg_id = 0x1001 CMD_SEND_FLEX →

ESP32: ← RSP_ACK (msg_id=0x1001)

Later:

ESP32: ← EVT_TX_DONE (msg_id=0x1001)

------------------------------------------------------------------------

12. LEGACY AT SUPPORT

-   AT commands remain supported
-   Used for human/manual interaction
-   Binary protocol used for host communication

Modes: - Binary (default) - Text (AT)

Switch commands: AT+TXT → switch to text AT+BIN → switch to binary

IMPORTANT: Both interfaces coexist logically. Binary = machine interface
AT = human/debug interface

------------------------------------------------------------------------

13. DESIGN PRINCIPLES

14. Every operation has msg_id

15. Never block waiting for execution

16. ACK != execution result

17. Events deliver final outcome

18. Host maintains state

19. Device is event-driven

------------------------------------------------------------------------

14. PROTOCOL COMPARISON

This protocol is equivalent to:

-   MAVLink (very similar design)
-   HDLC (framing concept)
-   CAN bus (message-based async model)

------------------------------------------------------------------------

END OF SPEC
